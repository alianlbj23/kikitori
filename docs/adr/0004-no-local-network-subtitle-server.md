# ADR-0004：不開本機網路埠（不提供 OBS 瀏覽器來源／網路字幕）

## 狀態

已採用（Accepted）。2026-11-06 使用者授權依建議決定。

## 日期

2026-11-06

## 背景

kikitori 的架構原則是不開網路埠：

- 引擎與 app 之間只走 stdio。
- 對外只有使用者設定的翻譯伺服器（client 端連線）。

競品比較提到以下做法：

- 在 127.0.0.1 開一個字幕網頁，給 OBS「瀏覽器來源」使用。
- 用 obs-websocket 的 `SendStreamCaption` 送 CEA-608 字幕。
- 用 QR code 把字幕分享到手機。

（`research_notes/競品比較/open_source_projects.md` 第 13 項、`commercial_products.md` 第 16 項）

## 決策

維持不開網路埠。OBS 整合只用已實作的文字檔輸出（F6，`文件\kikitori\obs\subtitle.txt`，OBS「文字（GDI+）→ 從檔案讀取」）。

## 理由

- **攻擊面**：即使只綁 127.0.0.1，本機任何程式與瀏覽器頁面都能連上。
  - 要防 DNS rebinding 與跨來源讀取，就得加 token、`Host` 檢查與 CORS 規則。
  - 這是長期維護的安全責任，而 kikitori 的主要使用者是觀眾，不是實況主。
- **已有的方案夠用**：文字檔輸出已能讓 OBS 顯示字幕，而且不需要任何網路設定。
  - 瀏覽器來源唯一多出的好處是套用 kikitori 的字幕樣式；OBS 文字來源本身也能設字型、顏色與外框。
- **obs-websocket 的限制**：
  - CEA-608 的字元集以拉丁字母為主，中日文能否正常顯示沒有查證（`research_notes/競品比較/open_source_projects.md` 列為風險）。
  - 需要 OBS 密碼，依專案規則只能從環境變數讀，對一般使用者不友善。

## 重新考慮的條件

以下兩項都成立時重新評估，並另寫一份 ADR 規定綁定位址、驗證方式與預設關閉：

- 使用者族群出現實況主（要在自己的直播上加字幕），而文字檔的樣式不夠用。
- 有不需要開埠的整合方式之外的明確需求，例如分享到手機。
