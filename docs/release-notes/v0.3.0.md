# kikitori v0.3.0

This release makes subtitles easier to read. Live translations no longer flicker as a whole line, multi-person collabs show who is speaking, and live interpreting marks you and the other person.
It also adds a few tools that help when watching streams: automatic fixes for words recognition gets wrong, stream info that keeps names translated consistently, shortcuts to pause and look back at subtitles, and a warning when the background music is too loud.
The research behind each item (top conferences and industry practice) and the implementation details are in `docs/specs/v0.3-features.md` and `docs/specs/speaker-labels.md` (in Chinese).

## New features

### Speaker labels (multi-person collabs)

- **Each subtitle starts with "Speaker 1, 2…"**: under "Audio source" in the left sidebar, set "Speaker labels" to "Guess how many" or to a fixed 2–6 speakers. After you press Start, the transcript, the subtitle window and exported subtitles all show who said each line. Video translation mode only.
- **Setting the number of speakers is more accurate when you know it**: on this project's 2–4 person tests built from Japanese YouTube clips, the share of lines labelled with the right speaker was:
  - 2 people: 92% when guessing, 96–100% with the count set.
  - 3–4 people: about 80–85%, so roughly 1 line in 5 goes to the wrong person.
  - With very loud background music (5 dB), at most about 7 points lower.
- **Rename and merge**: click a label in the transcript to rename it (for example to the streamer's name); the subtitle window follows. Give two labels the same name and they show as one person. Names last for the current session; the next session starts again from "Speaker 1".
- The speaker model (3D-Speaker CAM++, about 27 MiB, Apache-2.0) is downloaded the first time you choose speaker labels. It is not part of the installer and can be deleted on the Models page. Each line takes only about 0.05 s more (CPU).

### Easier-to-read subtitles

- **Live translations are split into a stable part and a changing part**: like the original, the beginning of the translation that will not change is shown normally and the tail that may still change is faded. When the new translation is just the start of the old one, the screen stays as it is instead of flickering.
- **No jumping, new words fade in**: a line that is still being spoken never gets shorter in the subtitle window, so the block does not jump up and down when the tail changes; newly appeared words fade in (no animation when the system's "reduce motion" setting is on).
- **Reading layout** (Settings → Subtitles):
  - Original text size (50–150% of the translation) and position (above or below the translation). Learners of Japanese can make the original bigger and put it underneath.
  - Maximum line width: long sentences wrap into two shorter lines so your eyes do not have to sweep across the whole screen.
  - Longer display time for longer lines: 4 characters per second for Chinese, Japanese and Korean, 15 for other languages, without letting subtitles fall behind.
  - Furigana can be shown only the first time a word appears in the session (subtitle window only).

### Live interpreting

- **"You" and "Them" labels**: each line is marked "You" or "Them"; the subtitle window shows the label when the speaker changes. Exported subtitles carry the labels too.
- **"Could you say that again?"**: while interpreting, press Ctrl+Alt+R and the subtitle window shows "Sorry, could you say that again?" **in the other person's language** for 5 seconds (pre-written for all 20 languages, no translation needed).

### More accurate translation

- **Recognition fixes**: under "Recognition fixes" in Settings → Glossary, write one rule per line as `wrong => right`, for example `ホロ ライブ => ホロライブ`. The fixes apply to the recognition result, so the screen, the translation and the transcript all use the corrected text. Up to 200 rules; a malformed line is pointed out by its line number.
- **Add to the glossary from the transcript**: select part of an original in the transcript and press "Add to glossary" to create an entry with the original filled in.
- **Stream info**: in "About this stream" in the left sidebar, enter the streamer's name, the game, collab members, or paste the stream description (up to 500 characters). The translator uses it as reference only, so names come out the same each time and the info itself is not translated into the subtitles.

### Subtitle window and warnings

- **Pause subtitles** with Ctrl+Alt+P: the subtitle window freezes while the transcript and OBS keep going; press again to jump back to the newest line.
- **Recent subtitles** with Ctrl+Alt+H: the subtitle window briefly shows the last 10 lines, closing after 8 seconds or when you press again.
- **Reset subtitle window position** (Settings → Subtitles): when the subtitle window ends up somewhere you cannot see (for example on an unplugged monitor), this moves it back to the main screen at its default size.
- **Loud background warning**: when the background music is about as loud as the voices for 15 seconds, the status bar warns that recognition may get worse.

On macOS the shortcuts use ⌘+Option with the same letter.

## Upgrading

- **Your settings carry over.** New options have defaults, so there is nothing to set up again.
- Speaker labels are off by default; the new reading layout options default to the same look as 0.2.0.
- If another app already uses Ctrl+Alt+R/P/H, the Transcript page marks that shortcut as unavailable; everything else keeps working.

## Known limitations

- **The speaker label numbers come from stitched-together YouTube clips, not real collab recordings**: the test data has no people talking over each other, no very short backchannels (under 1 second) and no one switching voices.
  Accuracy on real streams may be lower. Lines shorter than 1 second never start a new speaker and may have no label.
- Speaker labels are not written to the OBS text file and are not used in live interpreting (which already has "You" / "Them").
- The thresholds of the loud background warning (−30 dBFS, within 6 dB) are educated guesses that have not yet been tuned on stream recordings.
- Stream info is used only with the default Qwen3.5 prompt format; HY-MT and Sakura follow their official templates and do not get it.
- The other limitations of 0.2.0 still apply (see `docs/release-notes/v0.2.0.md`).
