# 評測：Silero VAD 的重置策略

> 暫時性實驗，不屬於正式程式碼。日期：2026-11-05；Silero VAD v6.2.3（ONNX，`kikitori.vad.SileroVad`）、onnxruntime 1.31.1、Python 3.12。
> 規格：`docs/specs/vad-segmenter.md`「評測」一節。結論已寫回規格與 `ResetPolicy` 的預設值。

## 怎麼重跑

```text
uv run python -I experiments/silero_reset/menu.py
```

選單：`1. 下載 MUSAN`（約 11.09 GB，確認後才下載，可續傳）→ `2. 產生評測音軌` → `3. 執行評測` → `4. 離開`。
結果寫入 `data/results.md`（彙總、明細、前文對照）與 `data/results.json`。`data/` 已被 git 忽略。

## 素材與音軌版本

- **人聲**：`experiments/pipecat_vad/data/tracks/` 的動漫、VTuber 音軌（各 6 段、共 12 段，權利屬原權利人，只在本機）。
- **兩種版面**：
  - `original`：原本的版面，句間 0.15–1.5 秒。
  - `longgap`：同一批片段重新排列，句間 3–4 秒（保留 0.15、0.5 秒兩個短間隔）。原版面最長間隔 1.5 秒，加上 0.6 秒句尾停頓仍屬於句子，(c) 的 2 秒非人聲重置根本不會發生，必須另做長間隔版面才比得出差異。
- **背景**：白噪音、粉紅噪音（固定種子）；MUSAN 音樂依 `ANNOTATIONS` 的 vocals 欄分成「有人聲演唱」（`music_vocal`）與「純音樂」（`music_inst`）。每首取 8 秒（從 30 秒處起，避開前奏）串成一條背景。
- **兩種混法**：間隔填入（只換句間靜音，背景音量以 SNR 10 dB 計）；人聲底下疊加（SNR 20／10／5 dB，人聲功率只算正確區間內）。
- **設定**：(a) `a_stream_start`、(b) `b_after_utterance`、(c) `c_after_long_non_speech`（2.0 秒），以及前文對照 `a_no_context`（(a) + `context_samples=0`）。其餘參數皆為規格預設值（門檻 0.5／0.35、`min_speech_ms` 250、`pre_roll_ms` 200、`pause_secs` 0.6、`max_secs` 10）。

### MUSAN 下載

OpenSLR 主站與鏡像站速度在 0.01–2 MB/s 之間浮動，經選單確認後約 1 小時完成，下載期間沒有中斷，續傳沒有實際派上用場（只在單元測試中驗證）。解壓 `music/`、`noise/` 共 1,606 個檔案、5.3 GB。下載完成前，先用已下載前段的約 196 首音樂做了「換曲目重複」的檢查（見下方第二張表，`data/results_music_seeds.json`）；正式結果（第一張表）是下載完成後經選單 2、3 產出的。

正式結果用到的檔案（種子 20261105）：`music_vocal` = fma-0044、fma-0080、fma-wa-0092、jamendo-0016、0166、0167；`music_inst` = fma-0050、fma-0054、rfm-0041、hd-0069、hd-0030、jamendo-0179；`noise` = free-sound-0136、0695、0272、0739、0165、0025、0661、0172。

### 其他檢查

- **原始動漫、VTuber 音軌**：三種策略都抓到全部 12 段（漏抓 0/12）。
- **純噪音音軌**：白噪音、粉紅噪音（−30／−15 dBFS，靜音與噪音交錯 30 秒）三種策略都產生 0 句（`tests/test_vad_integration.py`）。
- **前文對照**：84 條音軌全部判定「機率異常偏低」。接 64 樣本前文時人聲區平均機率 0.419–0.839；不接前文時最高只有 0.0021，所有音軌都 0 句、全部漏抓。與官方 issue #771 描述的「約 0.001」一致。
- **推論時間**：每個 32 ms 視窗平均 0.18 ms（252 次執行平均；單次執行最高 0.25 ms），低於 1 ms 的目標。
- **提早切斷**多半來自片段內部本來就有 ≥ 0.6 秒的停頓（原始音軌各策略都是 4 次），與重置策略無關；它反映 `pause_secs` 的取捨，不在本評測範圍。
- 逐格漏報率在乾淨音軌也有約 23%：正確答案以「整個片段」為人聲區間，片段內的換氣、停頓與字尾都算人聲。

## 結論：預設 `ResetPolicy.AFTER_LONG_NON_SPEECH`（c）

- **(c) 整體略好**：全部 84 條音軌 AUC 最高（0.905）、漏報率最低、開始延遲最短（中位數 470 ms、P90 820 ms；(a) 490／876、(b) 556／1440），漏抓 42/504（(a) 43、(b) 49）。
- **優勢集中在「長間隔 + 音樂」**：句間 3–4 秒都是音樂時，(a) 的狀態被音樂帶偏，下一句開頭被低報（pipecat #6207 描述的現象）。純音樂 longgap：(a) 漏抓 9/48、P90 1469 ms → (c) 7/48、1021 ms；有人聲音樂 longgap：(a) 6/48、1602 ms → (c) 3/48、1204 ms。下載完成前用另外兩組曲目重複，結論相同（純音樂 13/96 → 7/96，有人聲 18/96 → 11/96）。
- **代價在「長間隔 + 噪音」**：MUSAN 雜音 longgap (a) 0/48、(c) 2/48，P90 798 → 1039 ms；白／粉紅噪音 longgap (a) 10/96、(c) 12/96。重置剛好落在語音開頭前時，那一句的開頭會晚一點確認（pipecat 回報約 1% 的句子晚 200–400 ms）。
- **沒有長間隔時 (c) 等於 (a)**：原始版面幾乎不觸發重置（重置 0–1 次），各指標完全相同。
- **(b) 不採用**：每句結束立刻重置，下一句開頭剛好落在模型重新暖機的期間，開始延遲 P90 普遍拉長到 1.2–2.2 秒，噪音 original 版面漏抓 16/96（(a)(c) 9/96）。
- **為什麼仍選 (c)**：主要情境是觀看媒體（動漫、直播），配樂比長時間雜訊常見；(c) 在音樂上的收益（漏抓少 5 段、P90 少約 0.4 秒）大於在噪音上的損失（漏抓多 4 段、P90 多約 0.1–0.24 秒）。但差距不大，**是小幅領先而不是壓倒性的結論**。
- **限制**：人聲只有 12 段、每條背景 6–8 個檔案。換 Silero 版本、或之後有更多真實素材（含背景音樂的實錄節目）時應重跑；若真實使用中雜訊場景更多，(a) 是合理的替代。
